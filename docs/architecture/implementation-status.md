# وضعیت پیاده‌سازی

این فایل وضعیت واقعی کد را از طراحی آینده جدا می‌کند.

## انجام‌شده
- [x] ساختار اولیه Django و تنظیمات environment
- [x] تنظیمات اولیه DRF با SessionAuthentication و پیش‌فرض دسترسی احراز‌شده
- [x] endpoint سلامت و تست‌های پایه
- [x] تنظیمات PostgreSQL و Docker Compose توسعه
- [x] فایل نمونه environment، قواعد Git ignore و راهنمای اجرا
- [x] workflow اولیه GitHub Actions برای Django checks و tests
- [x] مدل پایه UserProfile با نقش‌های کسب‌وکاری پیشنهادی
- [x] مدل اولیه Customer با UUID، شماره مشتری یکتا، نوع، وضعیت و مسئول پرونده
- [x] API اولیه فهرست/ایجاد/ویرایش مشتری با محدودیت staff و بدون حذف فیزیکی
- [x] serializer با اعتبارسنجی اولیه مشتری حقیقی/حقوقی
- [x] migrationهای اولیه برای accounts و customers
- [x] مدل پرونده تسهیلات با مشتری، نوع محصول، مبلغ، مدت، وضعیت و مسئول
- [x] API اولیه فهرست/ایجاد/ویرایش پرونده‌های تسهیلات با فیلتر وضعیت، مشتری و جست‌وجو و بدون حذف فیزیکی
- [x] مدل تاریخچه رویدادهای پرونده و ثبت خودکار ایجاد، تغییر وضعیت و یادداشت پیگیری
- [x] endpoint مشاهده تاریخچه و افزودن یادداشت پیگیری برای پرونده
- [x] اعتبارسنجی اولیه انتقال وضعیت‌ها و تست‌های مرتبط
- [x] جست‌وجوی مشتری با نام، شماره، تلفن و ایمیل و پشتیبانی ارقام فارسی/عربی
- [x] endpoint بایگانی مشتری به‌جای حذف فیزیکی
- [x] مجوزهای مبتنی بر نقش برای API مشتری و پرونده تسهیلات
- [x] محدودسازی پرونده‌های کارشناسان به پرونده‌های تخصیص‌یافته به خودشان
- [x] محدودسازی ایجاد پرونده برای کارشناس به مشتریانی که به آن‌ها دسترسی دارد
- [x] دسترسی فقط‌خواندنی برای نقش‌های مالی و حسابرسی
- [x] امکان ثبت تصمیم نهایی توسط تأییدکننده اعتباری فقط از وضعیت «در انتظار تأیید» و بدون اجازه ویرایش سایر فیلدها
- [x] جلوگیری از ثبت تصمیم نهایی اعتباری توسط کارشناس پذیرش/پرونده
- [x] endpoint دریافت CSRF token، ورود/خروج نشست داخلی، نمایش کاربر جاری و تغییر گذرواژه
- [x] ورود داخلی فقط برای کاربر فعال staff دارای نقش مجاز؛ حساب مشتری از مسیر ورود داخلی رد می‌شود
- [x] آزمون‌های پایه CSRF، ورود، خروج، تغییر گذرواژه و دسترسی نقش‌ها
- [x] تعریف دو مسیر نمایشی مستقل در رابط: وام فوری از امتیاز شرکت و وام از امتیاز حساب مشتری
- [x] مراحل اختصاصی هر مسیر، انتخاب مسیر در فرم و پرونده، نمایش پیشرفت و ثبت تغییر مرحله در تاریخچه محلی رابط

- [x] مدل ممیزی سراسری append-only برای رخدادهای امنیتی و تغییرات اصلی مشتری/پرونده
- [x] ثبت موفق/ناموفق بودن ورود کارکنان بدون ذخیره نام کاربری خام در رخداد شکست یا ثبت گذرواژه
- [x] محدودیت نرخ endpoint ورود با کلید ترکیبی IP و شناسه حساب نرمال‌شده
- [x] ثبت ممیزی ایجاد/ویرایش/بایگانی مشتری و ایجاد/ویرایش/تغییر وضعیت/یادداشت پرونده تسهیلات
- [x] آزمون‌های جدید برای محدودیت نرخ، ممیزی و جلوگیری از درج متن یادداشت در metadata ممیزی

## محدودیت‌های امنیتی و دامنه فعلی
- این ماتریس نقش‌ها نسخه اولیه است و باید با مالک کسب‌وکار و واحد تطبیق/ریسک تأیید شود.
- ورود مشتری به پنل مشتریان هنوز پیاده‌سازی نشده است و باید از ورود کارکنان جدا بماند.
- ورود throttling/rate limiting، پایش رخدادهای امنیتی، بازیابی گذرواژه و MFA هنوز اضافه نشده‌اند.
- استقرار API، دامنه نهایی، HTTPS و پیکربندی نهایی CSRF_TRUSTED_ORIGINS هنوز انجام نشده است.
- نقش تأییدکننده اعتباری فعلاً فقط می‌تواند تصمیم نهایی ثبت کند؛ گردش رسمی امضا، دلیل اجباری رد، تأیید مستقل و سیاست تعارض منافع هنوز کامل نیست.
- شماره مشتری و شماره پرونده هنوز تولید خودکار امن ندارند.
- حذف فیزیکی مشتری و پرونده از API غیرفعال شده است؛ سیاست نگهداری و بایگانی نهایی نیازمند تأیید کسب‌وکار است.
- تاریخچه رویدادهای پرونده جایگزین سامانه ممیزی سراسری و مقاوم در برابر دستکاری نیست.
- داشبورد Cloudflare هنوز به API جنگو متصل نیست.
- گردش کار دو مسیر امتیاز شرکت و امتیاز حساب مشتری در رابط Cloudflare پیاده‌سازی نمایشی است؛ تغییر مرحله و تاریخچه هنوز از API جنگو و پایگاه داده مرکزی استفاده نمی‌کنند.
- نام مراحل، چک‌لیست‌های اجرایی پیشنهادی‌اند و باید با فرایند واقعی شرکت و ضوابط روز بانک رسالت/واحد تطبیق تأیید شوند؛ پیشرفت رابط به معنی تأیید یا پرداخت بانکی نیست.

## کارهای باقی‌مانده
- [ ] اتصال پنل به API با ارسال credentials و هدر CSRF
- [ ] استقرار API Django روی میزبان Python-compatible و پیکربندی امن HTTPS
- [ ] MFA برای نقش‌های حساس و محدودیت نرخ توزیع‌شده با cache مشترک در استقرار چندنمونه‌ای
- [ ] پایش رخدادهای امنیتی، هشداردهی و سیاست نگهداری/دسترسی به audit log
- [ ] تکمیل گردش رسمی تصمیم اعتباری و audit trail سراسری
- [ ] بایگانی پرونده تسهیلات و بارگذاری امن اسناد
- [ ] lint، dependency review و اجرای CI برای آخرین تغییرات
- [ ] اتصال واقعی پیامک، پرداخت و امضا
- [ ] hardening و تست امنیتی مستقل پیش از استقرار

## اعتبارسنجی
آزمون‌های تازه برای ممیزی و محدودیت نرخ به مخزن اضافه شده‌اند. اجرای موفق CI برای آخرین تغییرات باید از GitHub Actions بررسی شود؛ محدودیت نرخ با cache پیش‌فرض محلی برای استقرار چندنمونه‌ای کافی نیست و باید cache مشترک پیکربندی شود. این نسخه برای توسعه است و برای production آماده نیست.
