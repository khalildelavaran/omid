# وضعیت پیاده‌سازی

این فایل وضعیت واقعی کد را از طراحی آینده جدا می‌کند.

## انجام‌شده
- [x] ساختار اولیه Django و تنظیمات environment
- [x] تنظیمات اولیه DRF با SessionAuthentication و پیش‌فرض دسترسی احراز‌شده
- [x] endpoint سلامت و تست‌های پایه
- [x] تنظیمات PostgreSQL و Docker Compose توسعه
- [x] فایل نمونه environment، قواعد Git ignore و راهنمای اجرا
- [x] workflow اولیه GitHub Actions برای Django checks و tests
- [x] مدل پایه UserProfile با نقش‌های کسب‌وکاری پیشنهادی
- [x] مدل اولیه Customer با UUID، شماره مشتری یکتا، نوع، وضعیت و مسئول پرونده
- [x] API اولیه فهرست/ایجاد/ویرایش مشتری با محدودیت staff و بدون حذف فیزیکی
- [x] serializer با اعتبارسنجی اولیه مشتری حقیقی/حقوقی
- [x] migrationهای اولیه برای accounts و customers
- [x] مدل پرونده تسهیلات با مشتری، نوع محصول، مبلغ، مدت، وضعیت و مسئول
- [x] API اولیه فهرست/ایجاد/ویرایش پرونده‌های تسهیلات با فیلتر وضعیت، مشتری و جست‌وجو و بدون حذف فیزیکی
- [x] مدل تاریخچه رویدادهای پرونده و ثبت خودکار ایجاد، تغییر وضعیت و یادداشت پیگیری
- [x] endpoint مشاهده تاریخچه و افزودن یادداشت پیگیری برای پرونده
- [x] اعتبارسنجی اولیه انتقال وضعیت‌ها و تست‌های مرتبط
- [x] جست‌وجوی مشتری با نام، شماره، تلفن و ایمیل و پشتیبانی ارقام فارسی/عربی
- [x] endpoint بایگانی مشتری به‌جای حذف فیزیکی
- [x] مجوزهای مبتنی بر نقش برای API مشتری و پرونده تسهیلات
- [x] محدودسازی پرونده‌های کارشناسان به پرونده‌های تخصیص‌یافته به خودشان
- [x] محدودسازی ایجاد پرونده برای کارشناس به مشتریانی که به آن‌ها دسترسی دارد
- [x] دسترسی فقط‌خواندنی برای نقش‌های مالی و حسابرسی
- [x] امکان ثبت تصمیم نهایی توسط تأییدکننده اعتباری فقط از وضعیت «در انتظار تأیید» و بدون اجازه ویرایش سایر فیلدها
- [x] جلوگیری از ثبت تصمیم نهایی اعتباری توسط کارشناس پذیرش/پرونده
- [x] اجباری شدن دلیل رد درخواست تسهیلات و جلوگیری از ایجاد پرونده با وضعیت نهایی؛ دلیل در تاریخچه پرونده ذخیره می‌شود و در metadata ممیزی عمومی کپی نمی‌شود
- [x] محدود شدن تصمیم نهایی اعتباری به نقش تأییدکننده اعتباری؛ مدیر سامانه نیز نمی‌تواند این مرز اختیار را دور بزند
- [x] endpoint دریافت CSRF token، ورود/خروج نشست داخلی، نمایش کاربر جاری و تغییر گذرواژه
- [x] ورود داخلی فقط برای کاربر فعال staff دارای نقش مجاز؛ حساب مشتری از مسیر ورود داخلی رد می‌شود
- [x] آزمون‌های پایه CSRF، ورود، خروج، تغییر گذرواژه و دسترسی نقش‌ها
- [x] تعریف دو مسیر نمایشی مستقل در رابط: وام فوری از امتیاز شرکت و وام از امتیاز حساب مشتری
- [x] مراحل اختصاصی هر مسیر، انتخاب مسیر در فرم و پرونده، نمایش پیشرفت و ثبت تغییر مرحله در تاریخچه محلی رابط
- [x] مدل ممیزی سراسری append-only برای رخدادهای امنیتی و تغییرات اصلی مشتری/پرونده
- [x] تاریخچه رخدادهای تسهیلات و وظایف با کنترل append-only در سطح مدل و queryset؛ قفل ردیف هنگام تغییر وضعیت تسهیلات برای کاهش خطر تصمیم‌های هم‌زمان مبتنی بر وضعیت کهنه
- [x] API فقط‌خواندنی و صفحه‌بندی‌شده رخدادهای ممیزی با دسترسی محدود به مدیر سامانه و حسابرس
- [x] فهرست خدمات با تعرفه، فعال/غیرفعال‌سازی، نام یکتای بدون حساسیت به حروف و مجوز مدیریت محدود به مدیر سامانه
- [x] ثبت رسید خدمات با محاسبه سمت سرور، کنترل تخفیف و دریافتی، تصویر ثابت تعرفه روی رسید، ممنوعیت ویرایش/حذف فیزیکی و ثبت ممیزی
- [x] جلوگیری از ثبت تکراری رسید با `Idempotency-Key`، fingerprint محتوای درخواست، بازپخش پاسخ قبلی و پاسخ `409` در صورت استفاده از کلید با payload متفاوت
- [x] API اولیه اسناد پرونده با ذخیره‌سازی خصوصی، بررسی امضای فایل، سقف ۱۰ مگابایت، دانلود attachment مجاز و فرایند پذیرش/اصلاح سند
- [x] جایگزینی کنترل‌شده سند ردشده بدون حذف نسخه قبلی، ثبت رابطه نسخه‌ها، ممیزی جایگزینی و قید یکتایی در دیتابیس برای جلوگیری از جایگزینی هم‌زمان
- [x] ثبت موفق/ناموفق بودن ورود کارکنان بدون ذخیره نام کاربری خام در رخداد شکست یا ثبت گذرواژه
- [x] محدودیت نرخ endpoint ورود با کلید ترکیبی IP و شناسه حساب نرمال‌شده
- [x] ثبت ممیزی ایجاد/ویرایش/بایگانی مشتری و ایجاد/ویرایش/تغییر وضعیت/یادداشت پرونده تسهیلات
- [x] تولید شماره قابل‌نمایش مشتری و پرونده تسهیلات در backend؛ شماره‌ها در API فقط‌خواندنی‌اند و ورودی کاربر نمی‌تواند آن‌ها را جعل کند
- [x] API مدیریت وظایف گردش کار متصل به پرونده تسهیلات با اولویت، مسئول، موعد، وضعیت و ثبت ممیزی
- [x] ماژول درخواست ضمانت با اتصال اجباری به پرونده تسهیلات، درخواست‌دهنده اختیاری و مستقل، شماره‌گذاری خودکار، مجوزهای دامنه‌ای و ثبت ممیزی
- [x] تاریخچه مستقل وظایف به‌صورت append-only؛ ثبت ایجاد، تغییر وضعیت، تغییر موعد، واگذاری و یادداشت پیگیری با API مشاهده رویدادها
- [x] فیلتر وظایف عقب‌افتاده، نشانگر `is_overdue` و خلاصه شمارش وظایف در محدوده دسترسی کاربر
- [x] API گزارش عملیاتی فقط‌خواندنی برای مشتریان، وضعیت تسهیلات، وظایف، درخواست‌های ضمانت و جمع مبالغ رسیدها با محدوده دسترسی نقش
- [x] schema ماشین‌خوان OpenAPI از مسیر `/api/v1/schema/` با دسترسی محدود به کارکنان دارای نقش داخلی
- [x] آزمون‌های جدید برای محدودیت نرخ، ممیزی و جلوگیری از درج متن یادداشت در metadata ممیزی

## محدودیت‌های امنیتی و دامنه فعلی
- این ماتریس نقش‌ها نسخه اولیه است و باید با مالک کسب‌وکار و واحد تطبیق/ریسک تأیید شود.
- ورود مشتری به پنل مشتریان هنوز پیاده‌سازی نشده است و باید از ورود کارکنان جدا بماند.
- محدودیت نرخ ورود کارکنان و تغییر گذرواژه پیاده‌سازی شده است؛ MFA، بازیابی گذرواژه، پایش و هشداردهی امنیتی هنوز باقی مانده‌اند.
- استقرار API، دامنه نهایی، HTTPS و پیکربندی نهایی CSRF_TRUSTED_ORIGINS هنوز انجام نشده است.
- نقش تأییدکننده اعتباری فعلاً فقط می‌تواند تصمیم نهایی ثبت کند و دلیل رد اجباری است؛ گردش رسمی امضا، تأیید مستقل و سیاست تعارض منافع هنوز کامل نیست.
- شماره مشتری و شماره پرونده در backend با شناسه تصادفی تولید می‌شوند؛ قالب شماره‌ها و سیاست برخورد/توالی باید متناسب با الزامات عملیاتی نهایی بازبینی شوند.
- حذف فیزیکی مشتری و پرونده از API غیرفعال شده است؛ سیاست نگهداری و بایگانی نهایی نیازمند تأیید کسب‌وکار است.
- تاریخچه رویدادهای پرونده جدا از ممیزی سراسری نگهداری می‌شود. ممیزی مرکزی در لایه برنامه append-only است، اما در برابر مدیر دیتابیس یا تغییر مستقیم پایگاه داده، زنجیره‌نگاری رمزنگاری‌شده/ذخیره‌سازی WORM ندارد.
- داشبورد Cloudflare هنوز به API جنگو متصل نیست؛ APIهای ضمانت و خدمات در این مرحله فقط در بک‌اند ثبت/قابل‌خواندن‌اند و رابط نمایشی همچنان از localStorage استفاده می‌کند.
- رسید خدمات فقط سابقه داخلی دریافت وجه است؛ تأیید تراکنش واقعی کارت‌خوان/درگاه یا reconciliation هنوز پیاده‌سازی نشده است.
- گردش کار دو مسیر امتیاز شرکت و امتیاز حساب مشتری در رابط Cloudflare پیاده‌سازی نمایشی است؛ تغییر مرحله و تاریخچه هنوز از API جنگو و پایگاه داده مرکزی استفاده نمی‌کنند.
- نام مراحل، چک‌لیست‌های اجرایی پیشنهادی‌اند و باید با فرایند واقعی شرکت و ضوابط روز بانک رسالت/واحد تطبیق تأیید شوند؛ پیشرفت رابط به معنی تأیید یا پرداخت بانکی نیست.

## اعتبارسنجی
در اجرای [GitHub Actions](https://github.com/khalildelavaran/omid/actions/runs/38984668241)، بررسی Django، `makemigrations --check --dry-run` و هر ۱۱۱ آزمون بک‌اند موفق بوده‌اند. محدودیت نرخ فعلی از cache پیش‌فرض محلی استفاده می‌کند؛ برای استقرار چندنمونه‌ای باید cache مشترک پیکربندی و در لبه نیز rate limit اعمال شود. این نسخه برای توسعه است و برای production آماده نیست.
